Application Serverless Text-to-Speech

Construisez une application Text-to-Speech 100 % serverless qui convertit du texte en audio grâce à Amazon Polly, orchestrée par AWS Lambda, Amazon API Gateway, Amazon DynamoDB, Amazon SNS et Amazon S3.

⏱ Durée estimée : 60 min 🎯 Niveau : Cloud Level 2 🇫🇷 Langue : Français ⚡ 100 % Serverless

Mise en contexte

Introduction

Pourquoi le serverless, et ce que vous allez construire.

L'objectif de ce lab est de mettre en œuvre une application Text-to-Speech en utilisant les services serverless d'AWS, et en particulier Amazon Polly qui permet la conversion d'un texte en audio.

Les services serverless sont entièrement managés par AWS : haute disponibilité, montée en charge, configuration et mises à jour (montées de version, patchs de sécurité) sont gérées automatiquement. Vous vous concentrez uniquement sur l'application à livrer.

L'application repose sur les services suivants :

  • Des fonctions AWS Lambda pour l'implémentation des traitements
  • Amazon API Gateway pour l'exposition des API
  • Amazon Polly pour la conversion du texte en audio
  • Un bucket Amazon S3 pour le stockage des fichiers MP3 générés
  • Une table Amazon DynamoDB (NoSQL) pour le stockage des données
  • Amazon SNS pour la gestion des notifications entre composants

L'application utilise deux flux : l'un pour envoyer un texte à convertir en MP3, l'autre pour récupérer le fichier MP3 généré. Le traitement est asynchrone : l'utilisateur reçoit immédiatement un identifiant pendant que la conversion se poursuit en arrière-plan.

Vue d'ensemble

Architecture & workflow

Le schéma ci-dessous présente le flux complet, de la requête web jusqu'à la lecture du MP3.

i

Flux d'envoi (1→8) : la page web appelle l'API REST → API Gateway déclenche NewPost → écriture dans DynamoDB + publication sur SNS → ConvertToAudio appelle Polly → le MP3 est stocké dans S3 et DynamoDB est mise à jour.

Flux de récupération (9→10) : la méthode GET appelle GetPost qui lit DynamoDB, puis le navigateur lit le MP3 directement depuis S3.

Étape 3

Vérification du topic Amazon SNS

Amazon SNS

La conversion d'un texte en audio s'appuie sur deux fonctions Lambda découplées par un topic SNS. Vous allez vérifier que le topic TextToSpeech-new_posts existe et noter son ARN.

Le découplage par SNS permet des appels asynchrones : l'utilisateur reçoit immédiatement l'identifiant de sa demande sans attendre la fin de la conversion — utile pour les textes volumineux (100 000 mots ou plus) qui peuvent prendre plusieurs minutes.

Procédure

  3. Vérifiez que le topic TextToSpeech-new_posts apparaît dans la liste, puis cliquez dessus.
  4. Notez l'ARN du topic (format arn:aws:sns:…) — vous en aurez besoin pour configurer la fonction Lambda.

import boto3
import os
import uuid

def lambda_handler(event, context):

    recordId = str(uuid.uuid4())
    voice = event["voice"]
    text = event["text"]
    user = event["user"]

    print('Generating new DynamoDB record, with ID: ' + recordId)
    print('Input Text: ' + text)
    print('Selected voice: ' + voice)
    print('User: ' + user)

    #Creating new record in DynamoDB table
    dynamodb = boto3.resource('dynamodb')
    table = dynamodb.Table(os.environ['DB_TABLE_NAME'])
    table.put_item(
        Item={
            'id' : recordId,
            'text' : text,
            'voice' : voice,
            'status' : 'PROCESSING',
            'user' : user
        }
    )

    #Sending notification about new post to SNS
    client = boto3.client('sns')
    client.publish(
        TopicArn = os.environ['SNS_TOPIC'],
        Message = recordId
    )

    return recordId

Fonction Lambda « Convert to Audio »

AWS Lambda Amazon Polly S3 SNS

Cette fonction convertit le texte stocké dans DynamoDB en fichier audio MP3 grâce à Amazon Polly. Elle est déclenchée par un trigger SNS : chaque nouveau message reçu exécute ConvertToAudio.

i

Ce que fait la fonction : récupère le post ID depuis l'événement SNS → lit les infos dans DynamoDB → convertit le texte en flux audio via Polly → dépose le MP3 dans S3 → met à jour DynamoDB (status UPDATED + url).

Procédure

  1. Recherchez et ouvrez le service Lambda, puis cliquez sur la fonction existante PostReader_ConvertToAudio.
  2. Le code de la fonction est le suivant (déjà en place) :
Python · PostReader_ConvertToAudio cliquez pour afficher 
import boto3
import os
from contextlib import closing
from boto3.dynamodb.conditions import Key, Attr

def lambda_handler(event, context):

    postId = event["Records"][0]["Sns"]["Message"]

    print("Text to Speech function. Post ID in DynamoDB: " + postId)

    #Retrieving information about the post from DynamoDB table
    dynamodb = boto3.resource('dynamodb')
    table = dynamodb.Table(os.environ['DB_TABLE_NAME'])
    postItem = table.query(
        KeyConditionExpression=Key('id').eq(postId)
    )

    text = postItem["Items"][0]["text"]
    voice = postItem["Items"][0]["voice"]
    user = postItem["Items"][0]["user"]

    rest = text

    # Polly handles ~1500 chars per call, so we split into ~1000-char blocks.
    textBlocks = []
    while (len(rest) > 1100):
        begin = 0
        end = rest.find(".", 1000)

        if (end == -1):
            end = rest.find(" ", 1000)

        textBlock = rest[begin:end]
        rest = rest[end:]
        textBlocks.append(textBlock)
    textBlocks.append(rest)

    #For each block, invoke Polly, which transforms text into audio
    polly = boto3.client('polly')
    for textBlock in textBlocks:
        response = polly.synthesize_speech(
            OutputFormat='mp3',
            Text = textBlock,
            VoiceId = voice
        )

        #Save the audio stream to Lambda's /tmp directory
        if "AudioStream" in response:
            with closing(response["AudioStream"]) as stream:
                output = os.path.join("/tmp/", postId)
                with open(output, "wb") as file:
                    file.write(stream.read())

    s3 = boto3.client('s3')
    s3.upload_file('/tmp/' + postId,
      os.environ['BUCKET_NAME'],
      user + "/" + postId + ".mp3")
    s3.put_object_acl(ACL='public-read',
      Bucket=os.environ['BUCKET_NAME'],
      Key= user + "/" + postId + ".mp3")

    location = s3.get_bucket_location(Bucket=os.environ['BUCKET_NAME'])
    region = location['LocationConstraint']

    if region is None:
        url_begining = "https://s3.amazonaws.com/"
    else:
        url_begining = "https://s3-" + str(region) + ".amazonaws.com/"

    url = url_begining \
            + str(os.environ['BUCKET_NAME']) \
            + "/" + user + "/" \
            + str(postId) \
            + ".mp3"

    #Updating the item in DynamoDB
    response = table.update_item(
        Key={'id':postId},
          UpdateExpression=
            "SET #statusAtt = :statusValue, #urlAtt = :urlValue",
          ExpressionAttributeValues=
            {':statusValue': 'UPDATED', ':urlValue': url},
        ExpressionAttributeNames=
          {'#statusAtt': 'status', '#urlAtt': 'url'},
    )

    return

Fonction Lambda « Get Posts »

AWS Lambda DynamoDB

Cette troisième fonction Lambda récupère les informations des demandes stockées dans DynamoDB : soit un post précis par son id, soit tous les posts d'un utilisateur via l'index user-index.

Procédure

  1. Recherchez et ouvrez le service Lambda, puis cliquez sur la fonction existante PostReader_GetPost.
  2. Le code de la fonction est le suivant :
Python · PostReader_GetPost cliquez pour afficher 
import boto3
import os
from boto3.dynamodb.conditions import Key, Attr

def lambda_handler(event, context):

    postId = event["postId"]
    user = event["user"]

    dynamodb = boto3.resource('dynamodb')
    table = dynamodb.Table(os.environ['DB_TABLE_NAME'])

    if postId=="*":
        items = table.query(
            IndexName='user-index',
            KeyConditionExpression=Key('user').eq(user)
        )
    else:
        items = table.query(
            KeyConditionExpression=Key('id').eq(postId)
        )

    return items["Items"]

Exposition des Lambda via API Gateway

Amazon API Gateway AWS Lambda

Dernière brique côté back-end : exposer les fonctions Lambda en tant que service web via Amazon API Gateway, pour les appeler en HTTP. Vous créez une méthode POST (vers NewPost) et une méthode GET (vers GetPost).

Création de la ressource

  1. Recherchez et ouvrez le service API Gateway, puis cliquez sur l'API PostReaderAPI.
  2. Cliquez sur Create Resource.
  3. Dans Resource Name, saisissez votre identifiant (première lettre du prénom + nom, ex. jsmith).
  4. Vérifiez que la ressource est à la racine et que le Resource Path est bien /xxx, puis créez-la.

Méthode POST → NewPost

  1. Sélectionnez votre ressource, cliquez sur Create Method.
  2. Choisissez la méthode POST et validez.
  3. Renseignez :
    • Integration type : Lambda function
    • Lambda Region : eu-west-3 (ou votre région)
    • Lambda Function : XXX-PostReader_NewPost (ou la fonction existante PostReader_NewPost)
  4. Créez la méthode et validez le message en cliquant sur OK.

Activer CORS

  1. Sélectionnez la méthode POST créée, cliquez sur Enable CORS et validez.
  2. Une nouvelle méthode OPTIONS apparaît alors dans votre ressource.
i

Méthode GET : répétez la même procédure pour créer une méthode GET pointant vers PostReader_GetPost, puis activez CORS.

Déployer l'API

  1. Cliquez sur Deploy API.
  2. Deployment Stage : Lab-TextToSpeech, puis cliquez sur Deploy.
  3. Copiez l'URL d'invoke obtenue — vous en aurez besoin à l'étape suivante.

Authentifier l'accès avec Amazon Cognito

★★★★

N'autorisez l'usage de l'application qu'aux utilisateurs connectés. Avancez par étapes : testez après chacune.
