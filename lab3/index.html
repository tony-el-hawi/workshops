Cloud Level 3 · GenAI Serverless

Galerie Imaginaire

Concevez un pipeline d'IA générative 100 % serverless : à partir d'un·e artiste inventé·e, générez une exposition virtuelle complète — dossier curatorial (texte), trois œuvres (images) et un audio-guide (audio) — orchestrée par Amazon Bedrock et AWS Step Functions.

⏱ Durée estimée : 75 min 🎯 Niveau : Cloud Level 3 🤖 Bedrock · Step Functions 🇫🇷 Langue : Français

Mise en situation

Scénario de l'atelier

Le contexte client. Comprendre pourquoi on construit ce pipeline avant le comment.

La Fondation Lumière Hélène, musée d'art contemporain reconnu pour ses expositions audacieuses, lance une plateforme expérimentale : « Galerie Imaginaire », un espace en ligne où le public conçoit des expositions fictives et explore les mouvements artistiques de façon interactive.

Le visiteur invente un·e artiste — un nom, un mouvement (impressionnisme, surréalisme, cubisme…), un thème — et la plateforme doit générer, en moins d'une minute, une exposition virtuelle complète : une notice biographique et curatoriale, trois œuvres illustrées accrochées dans une galerie, et un audio-guide qui raconte l'inspiration de l'artiste, comme dans un vrai musée.

L'équipe technique de la fondation est réduite et ne veut aucun serveur à gérer. En tant que consultant cloud, votre mission : faire vivre ce pipeline 100 % serverless en complétant la logique d'invocation d'Amazon Bedrock et en orchestrant l'ensemble avec AWS Step Functions.

Ce que vous allez apprendre

Objectifs pédagogiques

Ce lab cible deux compétences clés : Amazon Bedrock et AWS Step Functions.

  • ✓Invoquer des modèles Amazon Bedrock (texte et image) depuis AWS Lambda, via le bon inference profile
  • ✓Forcer une sortie JSON structurée d'un LLM (prompt engineering)
  • ✓Décoder une image base64 renvoyée par Bedrock et la stocker dans Amazon S3
  • ✓Synthétiser une narration avec Amazon Polly
  • ✓Construire dans le Workflow Studio une state machine Step Functions avec états Map, Parallel, Retry et Catch

Étape 1

Découvrir les modèles Amazon Bedrock

Avant de coder, prenez en main Amazon Bedrock dans le Playground et repérez les identifiants de modèle que vous utiliserez. Aucune activation n'est nécessaire : les modèles serverless sont déjà disponibles.

Sous-tâches

  1. Console Bedrock (région eu-west-1) → Playground → Chat / Text.
  2. Tester un prompt avec un modèle Nova pour observer la réponse.
  3. Noter les model IDs du lab : texte eu.amazon.nova-micro-v1:0 · image stability.stable-image-core-v1:0.
!

Profil d'inférence : en eu-west-1, les modèles texte Nova s'invoquent via un inference profile régional — d'où le préfixe eu. obligatoire. Utiliser l'ID brut amazon.nova-micro-v1:0 provoquerait une erreur.

★ Prêt ! Vous connaissez vos modèles et savez où les tester.

Tâche 1.1 — Ouvrir le Playground

  1. En haut de la console, recherchez et sélectionnez Amazon Bedrock. Vérifiez la région eu-west-1 (en haut à droite).

  3. Cliquez sur Select model → fournisseur Amazon → Nova Micro → Apply.

Tâche 1.2 — Tester un prompt

  1. Saisissez par exemple : « Décris en une phrase le mouvement surréaliste » et lancez (Run).

Étape 3

Lambda Painter — image (Bedrock)

Complétez GI-Painter pour générer une œuvre avec le modèle image Stability AI, décoder le base64 et stocker le PNG dans S3. Cette fonction sera appelée 3× en parallèle par l'état Map.

Sous-tâches

  1. Ouvrir GI-Painter.
  2. Compléter les 4 TODO : corps de requête Stability, invoke_model, lecture du base64, dépôt S3.
  3. Deploy + Test.
!

Schéma différent de Nova : le modèle Stability attend { "prompt", "aspect_ratio", "output_format" } et renvoie un tableau images de chaînes base64 — ce n'est pas le format de l'API Converse.

★ Painter opérationnel. Une œuvre est générée et déposée dans S3.

Tâche 3.1 — Compléter les TODO

TODO 1 — corps de requête Stability :

Python
request_body = {
    "prompt": full_prompt,
    "aspect_ratio": "1:1",
    "output_format": "png",
}

TODO 2 — invoquer le modèle image :

Python
response = bedrock.invoke_model(
    modelId=IMAGE_MODEL_ID,
    body=json.dumps(request_body),
    contentType="application/json",
    accept="application/json",
)

TODO 3 — récupérer l'image base64 :

Python
payload = json.loads(response["body"].read())
image_b64 = payload["images"][0]

TODO 4 — décoder + déposer dans S3 :

Python
image_bytes = base64.b64decode(image_b64)
s3.put_object(
    Bucket=BUCKET_NAME,
    Key=key,
    Body=image_bytes,
    ContentType="image/png",
)

Étape 5 · le cœur du lab

Orchestrer avec Step Functions (Workflow Studio)

La state machine GI-Galerie contient déjà l'état Curator branché. À vous de construire la suite dans le Workflow Studio (interface visuelle) : un état Parallel contenant un Map (3× Painter) et la branche AudioGuide, puis Assemble.

i

Déjà fourni : l'état Curator (sortie dans $.dossier). À construire : Map + Parallel + Retry/Catch + Assemble.

Sous-tâches

  1. Ouvrir GI-Galerie → Edit → Workflow Studio.
  2. Ajouter un Map sur $.dossier.artworks (MaxConcurrency 3) avec Painter comme itérateur.
  3. Envelopper Map et AudioGuide dans un état Parallel.
  4. Ajouter Retry (throttling Bedrock) et Catch (→ FAILED).
  5. Brancher Assemble en sortie, enregistrer, puis lancer une exécution.
★

Après Start execution, observez le graphe se colorer en vert étape par étape, avec les 3 Painter qui s'exécutent en parallèle.

★ Pipeline orchestré ! Vous maîtrisez Map, Parallel, Retry et Catch.

Tâche 5.1 — Ajouter l'état Map (3 œuvres en parallèle)

  1. Console Step Functions → GI-Galerie → Edit → Workflow Studio.
  2. Sous l'état Curator, glissez un état Map (catégorie Flow).
  3. Dans la config du Map : Item source = $.dossier.artworks ; Concurrency = 3.
  4. À l'intérieur du Map, glissez une action Lambda Invoke → fonction GI-Painter.
  5. Configurez le Payload de Painter pour passer exhibitionId, movement, l'index ($$.Map.Item.Index) et l'œuvre ($$.Map.Item.Value).

Tâche 5.2 — Envelopper dans un Parallel (images ‖ audio)

  1. Ajoutez un état Parallel autour du Map.
  2. Dans la 2ᵉ branche du Parallel, glissez Lambda Invoke → GI-AudioGuide (payload : exhibitionId, artist, dossier).
i

Les deux branches s'exécutent simultanément — c'est tout l'intérêt du Parallel : la génération d'images n'attend pas l'audio, et inversement.

Tâche 5.3 — Résilience : Retry & Catch

  1. Sur Painter et Curator, ajoutez un Retry sur les erreurs de throttling (ThrottlingException) avec un backoff exponentiel.
  2. Sur le Parallel, ajoutez un Catch States.ALL qui mène à un état marquant le job FAILED dans DynamoDB.
!

Leçon réelle : Bedrock applique du throttling (quotas de requêtes/min). Sans Retry, une rafale de 3 images peut échouer. Le backoff exponentiel résout ça proprement.

Tâche 5.4 — Assemble & exécution

  1. En sortie du Parallel, glissez Lambda Invoke → GI-Assemble (passez exhibitionId, dossier et le résultat du Parallel).
  2. Save, puis Execute avec l'input :
JSON · input d'exécution
{
  "exhibitionId": "sfn-test-001",
  "artist": "Élodie Vasseur",
  "movement": "Surréalisme",
  "theme": "la mémoire et le temps"
}
  1. Observez le graphe d'exécution : Curator → (Map ‖ AudioGuide) → Assemble, chaque nœud passant au vert.
  2. En cas d'erreur, ouvrez le nœud rouge pour lire l'input/output et la cause — c'est l'outil de debug clé de Step Functions.
★

Besoin d'un repère ? Le formateur dispose d'un corrigé ASL complet (galerie.solution.asl.json) si vous souhaitez comparer votre construction.
